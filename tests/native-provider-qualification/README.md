# Private cold provider qualification

The existing private activation workflow runs this bounded proof at its exact PR head on Linux
and Windows. It builds the feature-gated driver test executable from the current locked source,
executes the canonical retained-source runner, then makes a new detached source checkout for
production BUILD. It never changes public selection or installation behavior.

The frozen Vec registry and source hashes are independent receipt authorities. The proof retains
two providers × three cases (two allocation faults and typed score 13) × supported execution
targets, complete manifests/artifacts, and complete ordered cleanup traces. Windows executes
JavaScript and WebAssembly: twelve observations. Native executable RUN remains Linux x86-64
only, giving eighteen Linux observations. These exclusions are contractual, not ignored tests.

Native capture starts with `.zryna` absent. Bootstrap comparison follows native publication.
Cold score-13 reruns must reach complete execution and Commit, reject with the exact
Preparation/C1009 existing-bundle diagnostic, preserve all output bytes and leave no private
transaction. The evidence includes separate retained collision bundles and checkpoint counts.

Four mutation controls attempt source writes at execution, Manifest and Commit, plus replacement
of a source directory with identical file bytes. Windows prevention requires an actual sharing
violation (OS error 32), unchanged source bytes/identity and continued canonical score-13
execution. Pinned Rust 1.97.1 classifies error 32 as `Uncategorized`; admission requires that
exact kind/code pair. The runner prints the observed kind, raw code and message before checking
the denial, so rejected OS causes remain in its retained stderr. A successful mutation must
fail with Source/D3004 and leave no output. The directory
replacement also changes root metadata/index; it does not isolate the nested identity alone.

Production cold BUILD uses the ordinary private CLI with full architecture validation, with
Node/npm/pnpm absent from PATH and explicit pinned Cargo/Rustc. It emits three objects/modules,
including the existing Linux x86-64 ELF object on Windows; it does not execute that object on
Windows. BUILD is native first, then checks the exact collision and a complete bootstrap bundle
comparison using explicit pinned Node. The fresh checkout receives a separately recorded frozen
pnpm adapter install only after the native BUILD and collision checks. All tracked source and
executable hashes are rechecked.

`verify.py` independently admits strict receipts, source binding, exact command order, frozen
outcomes/traces, complete bundle inventories, and mutation/collision controls. Its hosted mode
also checks the live tool/test executable bytes and fresh source checkout. Archive admission
rechecks retained source and proof bytes but cannot attest that removed hosted executable paths
still exist; workflow run/job/attempt/artifact provenance must be bound separately.
`verify_test.py` supplies hostile evidence controls; they are verifier tests, not OS execution.

The bounded proof has 27 Linux or 20 Windows admitted cases: observations, cold collisions,
four mutation controls, cold BUILD and bootstrap comparison. Full M1–M3 parity, full fault
coverage, ordinary installed no-Node/no-pnpm/no-Cargo acceptance, integrated #417 readiness and
public activation remain open. Existing historical pinned-consumer receipts retain their own
source identity and do not qualify this current revision.

The [remaining logical fault corpus](corpus/README.md) has a separate exact-head execution and
receipt path. The three-test lane excludes that child module; its original observation, mutation
and cold publication census stays separate.
